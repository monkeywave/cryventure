## Jedes Byte überallhin verteilen

SubBytes verwirbelt Bytes, verschiebt sie aber nie. Die **Diffusionsschicht** holt das in zwei
Schritten nach:

- **ShiftRows** rotiert Zeile `r` der Zustandsmatrix um `r` Positionen nach links: Versätze 0, 1, 2, 3
  (FIPS 197, §5.1.2).
- **MixColumns** ersetzt jede Spalte durch eine feste Linearkombination ihrer vier Bytes (§5.1.3).

ShiftRows verteilt die vier Bytes einer Spalte auf vier *verschiedene* Spalten; MixColumns lässt dann
jedes Byte auf seine ganze Spalte wirken. Nach zwei Runden hängt jedes Ausgabebyte von jedem
Eingabebyte ab.

## Die MixColumns-Matrix

Jede Spalte wird mit einer zirkulanten Matrix über GF(2⁸) multipliziert:

<Formula caption="FIPS 197, Gleichung 5.6. Multipliziert wird in GF(2⁸), addiert per XOR.">
{`┌ s'₀ ┐   ┌ 02 03 01 01 ┐ ┌ s₀ ┐
│ s'₁ │ = │ 01 02 03 01 │ │ s₁ │
│ s'₂ │   │ 01 01 02 03 │ │ s₂ │
└ s'₃ ┘   └ 03 01 01 02 ┘ └ s₃ ┘`}
</Formula>

`02·a` ist **xtime**: links schieben, bei Überlauf `1B` per XOR addieren. `03·a = xtime(a) ⊕ a`.
Das erste Byte, ausgerechnet:

<Formula>
{`02·d4 ⊕ 03·bf ⊕ 01·5d ⊕ 01·30
=  b3  ⊕  da   ⊕  5d   ⊕  30   = 04`}
</Formula>

<WhyBox constant="{02 03 01 01}" title="MDS-Matrix, Verzweigungszahl 5">
  Die Matrix ist **MDS**: Für jede Eingabespalte ungleich null ergeben die Nicht-Null-Bytes von
  Eingabe und Ausgabe zusammen mindestens **5** – das Maximum bei 4 Bytes. Zusammen mit ShiftRows
  erzwingt diese „Wide-Trail“-Strategie mindestens 25 aktive S-Boxen in jedem Pfad über 4 Runden.
  Die kleinen Einträge 01, 02, 03 halten die Berechnung billig.
</WhyBox>

</LessonSection>

## Schnell in Software

Implementierungen multiplizieren Matrizen selten Byte für Byte. Tabellenbasierter Code fasst
SubBytes, ShiftRows und MixColumns in vier **T-Tabellen** zu je 1 KiB zusammen; Hardware erledigt
die ganze Runde mit einem Befehl. Siehe [Speicher & Hardware](../memory-and-hardware/).

</LessonSection>

<LessonSection part="break">

## ShiftRows weglassen

Ohne ShiftRows verlassen die Bytes einer Spalte diese Spalte nie. AES zerfällt in **vier unabhängige
32-Bit-Chiffren**: Ändert man ein Klartextbyte, ändert sich nur eine Spalte des Chiffretexts. Ein
Angreifer kann jede Spalte einzeln tabellieren oder angreifen – ein 2³²-Problem statt 2¹²⁸. Ein
Lab-Schalter für dieses Experiment folgt in einem späteren Meilenstein.

</LessonSection>
