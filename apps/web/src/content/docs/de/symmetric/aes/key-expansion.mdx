## Ein Schlüssel, viele Rundenschlüssel

AddRoundKey braucht für jede der `Nr + 1` Schlüsseladditionen einen frischen 16-Byte-Rundenschlüssel.
Die **Schlüsselexpansion** (KeyExpansion, FIPS 197, §5.2) leitet sie alle aus dem Chiffrierschlüssel
ab – als Liste von 32-Bit-Wörtern `w[0] … w[4·Nr + 3]`. Die ersten `Nk` Wörter sind der Schlüssel
selbst; jedes weitere Wort entsteht, indem das Wort `Nk` Positionen davor mit dem vorigen
Wort XOR-verknüpft wird. Bei jedem `Nk`-ten Wort wird das vorige Wort zuvor umgeformt (RotWord, SubWord,
⊕ Rcon); AES-256 wendet zusätzlich bei `i mod 8 = 4` nur SubWord an.

<KeyFacts>
  <KeyFact label="AES-128" value="44 Wörter · 176 B" kind="key" />
  <KeyFact label="AES-192" value="52 Wörter · 208 B" kind="key" />
  <KeyFact label="AES-256" value="60 Wörter · 240 B" kind="key" />
</KeyFacts>

<Formula caption="FIPS 197, §5.2 (Abbildung 11), für i = Nk … 4·Nr + 3.">
{`temp ← w[i−1]
if i mod Nk = 0:             temp ← SubWord(RotWord(temp)) ⊕ Rcon[i/Nk]
else if Nk = 8 and i mod 8 = 4:  temp ← SubWord(temp)
w[i] ← w[i−Nk] ⊕ temp`}
</Formula>

**RotWord** macht aus `[a₀ a₁ a₂ a₃]` das Wort `[a₁ a₂ a₃ a₀]`; **SubWord** wendet die S-Box auf
jedes Byte an.

</LessonSection>

## Ein Schritt zum Nachrechnen: w[4]

<Formula caption="FIPS 197, Anhang A.1, i = 4.">
{`w[3]                    09cf4f3c
RotWord                 cf4f3c09
SubWord                 8a84eb01
⊕ Rcon[1]   01000000 →  8b84eb01
⊕ w[0]      2b7e1516 →  a0fafe17 = w[4]`}
</Formula>

<WhyBox constant="Rcon" title="01 02 04 08 10 20 40 80 1b 36">
  `Rcon[j] = [x^(j−1), 00, 00, 00]`: aufeinanderfolgende Potenzen von `x` (`02`) in GF(2⁸), daher folgt
  auf `80` der Wert `xtime(80) = 1b`. Ohne sie entstünde jeder Rundenschlüssel nach exakt derselben
  Regel, die alle Bytepositionen gleich behandelt. Die Konstanten brechen diese **Symmetrie** innerhalb
  der Wörter und zwischen den Runden – und vereiteln damit Slide-Angriffe, die identische Runden ausnutzen.
</WhyBox>

AES-256 hat eine zweite Besonderheit: Bei `i mod 8 = 4` durchläuft das Wort noch einmal SubWord. So
wird der lange Schlüssel auch in der Mitte jedes 8-Wort-Blocks nichtlinear durchmischt.

</LessonSection>

<LessonSection part="memory">

## Expandierte Schlüssel leben länger

Die meisten Bibliotheken expandieren den Schlüssel einmal und halten alle Rundenschlüssel so lange im
Speicher, wie der Kontext besteht – 176 bis 240 Byte hochstrukturierter Daten. Weil jedes Wort über die obige
Regel mit seinen Nachbarn verknüpft ist, erkennt ein Scanner einen Schlüsselplan in einem
Speicherabbild und kann sogar Bitfehler korrigieren. So finden Cold-Boot-Angriffe AES-Schlüssel.

</LessonSection>

<LessonSection part="break">

## Die Rundenkonstanten auf null setzen

Setze jedes `Rcon` auf `00`, und alle übrigen Schritte – RotWord, SubWord, XOR – behandeln die vier
Bytes eines Worts gleich. Rotierst du jedes Schlüsselwort um ein Byte, kommt auch jedes Wort der
Rundenschlüssel um ein Byte rotiert heraus: Verwandte Schlüssel liefern vorhersagbar verwandte
Rundenschlüssel. Genau von dieser Struktur leben Related-Key- und Slide-Angriffe. Ein Lab-Schalter
für dieses Experiment folgt in einem späteren Meilenstein.

</LessonSection>
