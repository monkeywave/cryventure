## 1600 bits, five step mappings

The [sponge](../sponge/) of SHA-3 calls one fixed permutation, **Keccak-f[1600]**. Its state `A`
is a 5 × 5 array of **lanes**, each a 64-bit word `A[x, y]` (FIPS 202, §3.1). A round applies
five step mappings, `ι ∘ χ ∘ π ∘ ρ ∘ θ` (§3.3), and Keccak-f[1600] runs 12 + 2ℓ = **24 rounds**
with ℓ = log₂ 64 = 6 (§3.4).

<WhyBox constant="RC, ρ, π" title="why these constants">
  ι's round constants come from an LFSR with polynomial x⁸ + x⁶ + x⁵ + x⁴ + 1 (FIPS 202,
  Algorithm 5); ρ's offsets are triangular numbers along the walk (x, y) → (y, 2x + 3y)
  (Algorithm 2); π moves lane (x + 3y, x) to (x, y) (Algorithm 3). No table is chosen by hand.
</WhyBox>

<Lens only="story">

25 drawers of 64 marbles: each round mixes columns, spins and shuffles the drawers, lets
neighbours interfere, and drops in one marked marble.

The lab hashes "abc" with SHA3-256, the NIST example (CSRC, Examples with Intermediate Values).
The message fits one rate block of 136 bytes (FIPS 202, §6.1), so there is one `absorb`, one

## θ, ρ, π, χ, ι

<Formula caption="Keccak-f[1600] round on lanes, FIPS 202 §3.2.1–3.2.5 (x, y mod 5; ROT = rotate left on 64 bits; ¬ = NOT, ∧ = AND).">
{`θ:  C[x] = A[x,0] ⊕ A[x,1] ⊕ A[x,2] ⊕ A[x,3] ⊕ A[x,4]
    D[x] = C[x−1] ⊕ ROT(C[x+1], 1);   A[x,y] ⊕= D[x]
ρ:  A[x,y] = ROT(A[x,y], r[x,y])
π:  A'[x,y] = A[(x + 3y) mod 5, x]
χ:  A'[x,y] = A[x,y] ⊕ (¬A[x+1,y] ∧ A[x+2,y])
ι:  A[0,0] ⊕= RC[i]`}
</Formula>

θ spreads every bit into two columns (§3.2.1); ρ rotates within lanes, π permutes lanes
(§3.2.2–3.2.3). χ is the only map with an AND (§3.2.4): **degree 2** over GF(2), the sole
non-linear step. ι breaks the symmetry between rounds (§3.2.5).

The 24 RC words: `RC[i]` takes LFSR bits `rc(7i + j)` as bit `2ʲ − 1`, j = 0 … 6 (Algorithm 6).
FIPS 202 does not print them; the Keccak reference 3.0 (§1.2) lists `RC[0] = 0x1`,
`RC[1] = 0x8082`, … `RC[23] = 0x8000000080008008`.

<Lab labId="keccak-rc" producerId="keccak-constants" presetId="rc" layout="wordops:50|state:30|narration:20" />

ρ's walk starts at (1, 0) and gives step t the offset (t + 1)(t + 2)/2 mod 64. The matrix
[[0, 1], [2, 3]] mod 5 visits all 24 lanes except (0, 0), and the 24 triangular numbers are
distinct mod 64 (Algorithm 2; FIPS 202 Table 2).

## Little-endian lanes and ARMv8.2

FIPS 202 maps string bit `w(5y + x) + z` to `A[x, y, z]` (§3.1.2), and bit 0 of each byte is its
least significant (Appendix B.1). A lane is thus eight bytes read as a **little-endian** 64-bit
integer: ι's `RC[1] = 0x8082` changes the state bytes `82 80`. SHA-2 is big-endian (FIPS 180-4,
§3.1), so a little-endian core loads Keccak lanes without a byte swap.

Armv8.2-A adds FEAT_SHA3 (Arm ARM): `EOR3` XORs three registers (θ's column parity), `RAX1`
computes `a ⊕ ROT(b, 1)` (θ's D), `XAR` XORs and rotates right (θ's ⊕ D fused with ρ), and `BCAX`
computes `a ⊕ (b ∧ ¬c)` (χ in one instruction). The lab derives a clang-compiled round loop; every
register value is read from the trace above.

## Why 24 rounds

Remove χ and every step is linear or affine over GF(2) (FIPS 202, §3.2.1–3.2.5): the permutation
becomes one matrix plus a constant, and linear algebra inverts any output. Remove ι and every round
is the same map, and θ, ρ, π and χ treat all bit positions z alike (§3.2.1–3.2.4): rotating every
lane by the same amount would commute with the whole permutation.

Twenty-four rounds are a safety margin. Guo, Liao, Liu, Liu, Qiao and Song (J. Cryptology 33,
2020) found **actual collisions for 5-round** SHA3-224 and SHA3-256; full SHA-3 runs 24 rounds
(§3.4). Reduced-round results measure the margin; they do not break the standard.

<Lens level="cryptographer">

χ has algebraic degree 2 and the other maps are affine, so n rounds have degree at most 2ⁿ.
Guo et al. exploit this low degree by linearizing the first two rounds.

</Lens>

## Check yourself

<CheckQuestion
  id="keccak-nonlinear-step"
  number={1}
  question="Which step mapping of Keccak-f is non-linear?"
  options={['θ', 'ρ', 'χ', 'ι']}
  answer={2}
>
  χ combines two neighbouring lanes with AND (FIPS 202, §3.2.4), which makes it degree 2. θ, ρ and
  π only XOR, rotate and move bits; ι XORs a constant (§3.2.1–3.2.3, §3.2.5).
</CheckQuestion>

<CheckQuestion
  id="keccak-round-count"
  number={2}
  question="How many rounds does Keccak-f[1600] run?"
  options={['12', '18', '24', '80']}
  answer={2}
>
  Keccak-f[b] has 12 + 2ℓ rounds with ℓ = log₂(b/25) (FIPS 202, §3.4). For b = 1600 the lanes are
  64 bits, ℓ = 6, so 24 rounds.
</CheckQuestion>

<CheckQuestion
  id="keccak-lane-byte-order"
  number={3}
  question="In which byte order are the 64-bit lanes of the SHA-3 state stored?"
  options={[

    'Little-endian, unlike SHA-2',

    'Lanes are not byte-aligned',

>
  FIPS 202 maps string bit `w(5y + x) + z` to lane bit z (§3.1.2) with the least significant bit of
  each byte first (Appendix B.1), so a lane's first byte is its low byte. SHA-2 words are
  big-endian (FIPS 180-4, §3.1).
