## A hash made of XOR and one multiplication

GCM authenticates with **GHASH**, a keyed hash over 16-byte blocks. Its key is the **hash subkey**
`H = E_K(0¹²⁸)` (NIST SP 800-38D, §7.1). GHASH starts at zero and folds in one block at a time:
XOR the block in, then multiply by `H` (§6.4, Algorithm 2).

<Formula caption="GHASH, NIST SP 800-38D §6.4 (the spec calls the blocks Xᵢ; the lab calls them Bᵢ).">
{`Y₀ = 0¹²⁸
Yᵢ = (Yᵢ₋₁ ⊕ Bᵢ) • H        GHASH_H(B₁ … Bₘ) = Yₘ`}
</Formula>

The multiplication `•` lives in the field **GF(2¹²⁸)**: a block is a polynomial with 128 bits as
coefficients, addition is XOR, and products are reduced modulo `x¹²⁸ + x⁷ + x² + x + 1` (§6.3). It
works like [GF(2⁸)](../../../foundations/gf256/) in AES, only 16 times wider.

<KeyFacts>
  <KeyFact label="Block = element" value="128 bits" kind="state" />
  <KeyFact label="Addition" value="XOR" kind="state" />
  <KeyFact label="Modulus" value="x¹²⁸+x⁷+x²+x+1" kind="constant" />
  <KeyFact label="Hash subkey H" value="E_K(0¹²⁸)" kind="key" />
</KeyFacts>

<Lens only="story">

Think of a running total: add the next block, then stir with the secret `H`. After the last block,
the total depends on every bit of every block.

</Lens>

## Algorithm 1: shift right, reduce with R

GCM numbers bits the "reflected" way: **bit 0 is the most significant bit of byte 0** and is the
coefficient of `x⁰`; bit 127 is the LSB of byte 15 (SP 800-38D, §6.3). Multiplying by `x` therefore
shifts the block **right**.

<Formula caption="Algorithm 1, NIST SP 800-38D §6.3: X • Y, with x₀ … x₁₂₇ the bits of X. In each GHASH step the first factor is Yᵢ₋₁ ⊕ Bᵢ and the second is H.">
{`Z₀ = 0¹²⁸,  V₀ = Y
for i = 0 … 127:
    Zᵢ₊₁ = Zᵢ ⊕ Vᵢ   if xᵢ = 1,   else Zᵢ
    Vᵢ₊₁ = Vᵢ >> 1   if LSB₁(Vᵢ) = 0,   else (Vᵢ >> 1) ⊕ R
return Z₁₂₈              R = 11100001 ‖ 0¹²⁰`}
</Formula>

`V` runs through `H, H•x, H•x², …`, and bit `xᵢ` decides whether `H•xⁱ` joins the sum. The lab's
block starts with `0x03 = 00000011`, so `Z` stays 0 until iteration 6.

<WhyBox constant="R = 0xe1 ‖ 0¹²⁰" title="the modulus, written backwards">
  When `V`'s last bit (the `x¹²⁷` term) is 1, the shift would create `x¹²⁸`. Since
  `x¹²⁸ ≡ x⁷ + x² + x + 1`, those terms are XORed back in: bits 0, 1, 2 and 7, which is the first
  byte `11100001 = 0xe1` in GCM's reflected order (SP 800-38D §6.3).
</WhyBox>

<Lens level="cryptographer">

Expanded, `Yₘ = B₁•Hᵐ ⊕ B₂•Hᵐ⁻¹ ⊕ … ⊕ Bₘ•H` (SP 800-38D §6.4): a polynomial in `H` with the blocks
as coefficients.

</Lens>

</LessonSection>

## Bytes in, reflected bits inside

GHASH takes blocks as byte strings, so its input needs no byte swapping: the byte order is the
order on the wire. Only the bit numbering inside the field is reflected (SP 800-38D, §6.3), and
`>> 1` shifts the whole 128-bit string. Code that holds a block in two 64-bit big-endian words
must carry the bit that leaves the high word into the top of the low word.

In GCM, GHASH's input is laid out as follows (§7.1); each part is zero-padded to whole blocks:

<Formula caption="GHASH input in GCM, NIST SP 800-38D §7.1.">
{`A ‖ 0ᵛ ‖ C ‖ 0ᵘ ‖ [len(A)]₆₄ ‖ [len(C)]₆₄`}
</Formula>

The final **length block** stores both lengths in bits, as 64-bit integers (§7.1). Without it, a
message and the same message with extra zero blocks in front would hash alike: `Y` stays 0 while
zero blocks are folded in (§6.4).

</LessonSection>

<LessonSection part="break">

## Why GHASH alone is not a MAC

GHASH is **linear** in its input: for inputs of equal length, `GHASH_H(X ⊕ X′) = GHASH_H(X) ⊕
GHASH_H(X′)`, because each block is just multiplied by a fixed power of `H` (SP 800-38D §6.4). Anyone
who knows `H` can compute GHASH for any message, so `H` must stay secret; that is why it is derived
from the key as `E_K(0¹²⁸)` (§7.1).

Even with `H` secret, bare GHASH values would expose linear relations between inputs. GCM therefore
never sends GHASH directly: it masks it with `E_K(J0)`, which depends on the nonce (§7.1). The [GCM lesson](../gcm/) shows that step and why the nonce must never
repeat.

<Lens level="cryptographer">

GHASH is an almost-XOR-universal hash: for distinct inputs of `m` blocks, their difference is a
nonzero polynomial of degree ≤ `m` in `H`, so at most `m` of the 2¹²⁸ values of `H` make them
collide (McGrew–Viega, INDOCRYPT 2004). That bound holds only while `H` is unknown.

</Lens>

</LessonSection>
