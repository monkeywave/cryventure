# M3 — Modes I: design brief

This is the shared contract for everyone working on M3. The decisions here are binding; record any
deviation in `docs/STATUS.md`. The format follows `docs/M2.md`.

## 0. M2 backlog items fixed first

### 0a. Initial-state narration (step −1)

- `StateFacet.initialNarration?: I18nRef` (optional, additive). It narrates `facet.initial`, before
  step 0.
- `NarrationFacet.entries` may start with an entry at `step: -1`. `narrationFromState` emits it when
  `initialNarration` is set. `narrationAt(facet, -1)` returns it, and dense O(1) lookup still works
  (offset by one when entry 0 is step −1).
- `MathFacet.steps` may start with `step: -1`, and `mathStepAt(facet, -1)` returns it.
- viz: at step −1 the narration and caption show the producer's initial narration when there is one,
  else the generic `ui.narration.initial`. The math view renders a step −1 entry like any other.
- Migrations:
  - **gf256:** remove the `load` op (xtime/gmul/ginv). The loaded operands live in `initial`, and the
    `load`/`loadZero` narration and math move to step −1.
  - **aes-sbox:** remove `load`. Its narration and `.math.load` move to step −1.
  - **xor:** `loadMessage`/`loadKey` are removed. Message and key are in `initial`, and one initial
    narration introduces both.
  - **endian:** gets an initial narration (it has no load op).
  - **aes:** keeps its `input` op (FIPS 197 `state ← in` is a real step).
- Lessons drop `startAt="op:load"`, since the default start is already step −1.
- The contract kit checks the initial-narration key and its `{{params}}` in EN and DE.

### 0b. Stable quiz question ids

- `<CheckQuestion id="ecb-penguin" number={1} …>`: `id` is **required**, kebab-case, unique per
  lesson and identical in EN and DE. `number` is display-only from now on, so renumbering is allowed.
  The ids never change.
- Progress v2: `lessons[k].quiz` is keyed by question id. The v1→v2 migration moves the old
  number-keyed entries to `lessons[k].legacyQuiz` (keyed by number).
  - Readers resolve `quiz[id] ?? legacyQuiz[String(number)]`.
  - Recording an answer writes `quiz[id]` and deletes the matching `legacyQuiz` entry.
  - This needs no global id index. Every place that reads progress already knows `(id, number)`: the
    question island has its own, and the progress page passes the per-lesson list from the MDX source.
- Export/import accepts v1 and v2 (v1 goes through the migration).
- The parser rejects ids that aren't kebab-case. Duplicate ids in one lesson fail the build.

## 1. Ports: `BlockCipher` in core

```ts
// packages/core/src/ports.ts
export interface BlockCipher {
  readonly id: string;                 // producer id, e.g. 'aes'
  readonly blockSize: number;          // bytes
  readonly keySizes: readonly number[];// bytes
  encryptBlock(key: Uint8Array, block: Uint8Array): Uint8Array;
  decryptBlock(key: Uint8Array, block: Uint8Array): Uint8Array;
}
export interface PortMap { BlockCipher: BlockCipher }
export type PortName = keyof PortMap;
```

- `PrimitiveManifest.implements` becomes `PortName[]`.
- `PrimitiveModule.ports?: Partial<PortMap>`: a module exposes every port its manifest declares. The
  aes module turns its stub `blockCipher` into `ports.BlockCipher`. There is no tracer at mode level.
- The contract kit checks:
  - every declared port is present on the loaded module;
  - for `BlockCipher`: block and key sizes, a decrypt∘encrypt round trip, and that a wrong-length
    key or block throws.

## 2. Composites without plugin→plugin imports

- New param field kind **`port`**: `{ name: 'cipher', kind: 'port', port: 'BlockCipher', labelKey }`.
  - Its value is a producer id.
  - Its options are the registered producers whose manifest `implements` that port, labelled by
    their `titleKey`.
  - `validate()` only checks that the value is a kebab-case string. Whether a producer with that id
    exists is checked by the resolver.
- `run(params, { tracer?, resolve? })`. `resolve(port, id)` is **synchronous** and returns the port
  implementation or `undefined`. The run returns `{ ok: false, error }` (`core.error.portMissing`)
  when it is missing.
- `preparePorts(manifest, params, registry)` (core, async) loads the modules of every `port` param
  and returns the sync `resolve`. The web host, the contract kit, the oracles and the worker all use
  this one function. `runPrimitive` stays sync.
- Key sizes come from the resolved cipher. A wrong key length is a run error
  (`core.error.keyLength` with `{{sizes}}`), not a validate error.
- **i18n:** `labMessages` loads the producer's namespace plus the namespaces of **all** producers
  that are options of its `port` params. The learner can switch cipher on the client, so the server
  can't know which one ends up resolved.
- The `cbc(aes)` id grammar and `defineComposite` stay deferred. A lab is `producerId="cbc"` with
  `cipher: 'aes'` in its params.
- New param field kind **`text`**: `{ kind: 'text', maxLength }`, a UTF-8 string param rendered as a
  text input. It is used by the attack labs ("comment=…;admin=false").

## 3. Shared mode math in core (untraced reference)

- `core/padding/pkcs7.ts`:
  - `pkcs7Pad(data, blockSize)`
  - `pkcs7Unpad(data, blockSize) → { ok: true, data } | { ok: false, reason }`, where `reason` is
    `'empty' | 'not-block-aligned' | 'zero-pad-byte' | 'pad-too-long' | 'inconsistent-pad-bytes'`
  - `pkcs7Check(data, blockSize): boolean`, the oracle predicate
- `core/modes/{ecb,cbc,ctr}.ts`: `ecbEncrypt/Decrypt(cipher, key, data)`,
  `cbcEncrypt/Decrypt(cipher, key, iv, data)` and `ctrXor(cipher, key, counterBlock, data)`, all
  over the `BlockCipher` port, with no padding or tracing. CTR uses the standard incrementing
  function over the whole 128-bit block, big-endian, mod 2¹²⁸ (SP 800-38A B.1 with m = b).
- These functions are the reference for the traced primitives (each primitive asserts that its trace
  output equals them), the attack producers and the penguin worker. They follow the precedent of
  `core/math/gf256`, the shared math moved to core in M2.

## 4. Mode primitives `ecb`, `cbc`, `ctr`

| Param | ecb | cbc | ctr |
|---|---|---|---|
| `cipher` (port BlockCipher) | ✓ | ✓ | ✓ |
| `keyHex` | ✓ | ✓ | ✓ |
| `ivHex` (16 B) | — | ✓ | — |
| `counterHex` (16 B initial counter block) | — | — | ✓ |
| `inputHex` (≤ 64 B, i.e. 4 blocks) | ✓ | ✓ | ✓ |
| `direction: encrypt\|decrypt` | ✓ | ✓ | — (CTR is its own inverse) |
| `padding: pkcs7\|none` | ✓ | ✓ | — |

- **Facets:** `state`, `values`, `narration`, `chain`, `wire`.
- **State regions:** `input`, `output`, a per-block `work` register (the cipher's in/out), `iv`/`chain`
  (cbc), and `counter`/`keystream` (ctr).
- **Scope levels:** block → op. The ops are, for example:
  - `pad` (once)
  - `xorChain`
  - `encryptBlock` / `decryptBlock`, which is opaque: E_k with its input and output in state and
    narration
  - `xorKeystream`
  - `emit`
  - `unpad`
- **Initial state:** input (+ iv/counter), with an initial narration.
- **Decrypt with invalid PKCS#7** is **not** a run error. The last step `unpad` narrates the reason,
  and `output` carries `padded` (all blocks) instead of `plaintext`.
- **Outputs:**
  - encrypt: `ciphertext`
  - decrypt: `plaintext` (or `padded`)
  - ctr: `output` + `keystream`
- **Conformance** (`vectors/conformance.json`) uses SP 800-38A App. F, `padding: none`:
  - F.1.1–F.1.6 ECB-AES128/192/256 encrypt and decrypt
  - F.2.1–F.2.6 CBC
  - F.5.1–F.5.6 CTR
- **Oracles:** `tools/src/oracles/modes.oracle.test.ts` compares against `@noble/ciphers` `ecb`,
  `cbc` and `ctr` (fast-check, random keys, IVs and lengths, PKCS#7 on and off).

## 5. Nested traces: mode level only

- M3 ships the mode-level trace only. Each block-cipher call is one opaque step, with the block in
  and out in state and narration.
- **Deviation:** there is no `math` facet for E_k. The math facet's terms are ≤ 32-bit GF(2⁸) terms,
  and 128-bit blocks are shown in state and the chain view instead.
- **"Zoom into block i":** a `chain` node of kind `cipher` may carry
  `zoom: { producerId: 'aes', params: { keyHex, plaintextHex, detail: 'op' } }`.
  - It is set for encryptions only, since the AES lab encrypts.
  - The view calls `useLabActions().labHref?.(producerId, params)`. This is new, optional and wired
    by the web app.
  - The web app returns `<base><lang>/lab/<producerId>/#lab=<producerId>&p=…`.
- **New standalone lab route** `src/pages/[lang]/lab/[id].astro` (PLAN §1):
  - one page per registered producer;
  - full width via `<StarlightPage>`;
  - all of the producer's views;
  - title from `titleKey`;
  - `labId = producerId`;
  - not in the sidebar;
  - excluded from Pagefind.
- Lazy child traces (`children`) wait until HKDF and TLS need them.

## 6. New facets

### `chain`: block-mode dataflow (one lane per block)

```ts
type ChainNodeKind = 'input' | 'iv' | 'counter' | 'xor' | 'cipher' | 'keystream' | 'output' | 'pad';
interface ChainNode {
  id: string;            // stable, e.g. 'b2.xor'
  block: number;         // lane, 0-based; -1 = before the first lane (IV, padding)
  kind: ChainNodeKind;
  label: I18nRef;
  bytes: number[];       // value shown in the node
  valueRef?: string;     // ValueRef id for linked brushing
  activeAt: number;      // state step at which the node gets its value (-1 = initial)
  zoom?: { producerId: string; params: Record<string, string> };
}
interface ChainEdge { from: string; to: string; activeAt: number }
interface ChainFacet {
  kind: 'chain'; schemaVersion: 1;
  mode: 'ecb' | 'cbc' | 'ctr' | (string & {});
  direction: 'encrypt' | 'decrypt';
  formula: I18nRef;      // e.g. "C_i = E_k(P_i ⊕ C_{i−1})"
  nodes: ChainNode[]; edges: ChainEdge[];
}
```

- The contract kit checks:
  - unique node ids;
  - edge endpoints exist;
  - `activeAt` lies within [-1, steps-1] and is not earlier than the `activeAt` of an edge's
    sources;
  - label keys exist in EN and DE.

### `wire`: bytes as they travel

```ts
type WireRole = 'iv' | 'nonce' | 'ciphertext' | 'padding' | 'tag' | 'plaintext';
interface WireSegment { id: string; role: WireRole; label: I18nRef; bytes: number[]; valueRef?: string; block?: number }
interface WireFacet {
  kind: 'wire'; schemaVersion: 1;
  segments: WireSegment[];
  /** If set, clicking a bit/byte flips it via requestParams({ [flipParam]: newMaskHex }). */
  flip?: { param: string; maskHex: string };
  /** Per-step highlight: which byte offsets (over the concatenated segments) are active. */
  activeAt?: { step: number; offsets: number[] }[];
}
```

## 7. Views

| View | Requires | Purpose |
|---|---|---|
| `views/mode-chain` | `chain` | Lanes per block. Nodes light up at `activeAt` and edges animate (Motion, reduced-motion safe). The cryptographer lens shows `formula` and subscripted labels, the story lens hides hex detail. Cipher nodes show a "Zoom into block i" link when `labHref` and `zoom` exist. On a phone the lanes scroll horizontally inside the panel, never the page. |
| `views/wire` | `wire` | A packet-like strip of byte boxes coloured by role, with glyph and border. When `flip` is set, bytes are buttons (keyboard: Enter toggles 0x01, digits 0–7 pick a bit) that call `requestParams`. |

Both views follow EXTENDING ("Add a view"). Contract fixtures come from the real ecb, cbc and ctr
producers.

## 8. Attack labs: deterministic producers

All three take a `cipher` port param and use `core/modes`.

| Producer | Params | Facets | Trace |
|---|---|---|---|
| `cbc-bitflip` | cipher, keyHex, ivHex, `plaintext` (text), `flipMaskHex` (over IV‖C) | state, values, narration, wire (with `flip`), chain | encrypt → apply mask → decrypt; highlight the scrambled block and the targeted flipped byte |
| `ctr-reuse` | cipher, keyHex, counterHex, `plaintextA`, `plaintextB` (text), `crib` (text), `cribOffset` | state, values, narration, wire | C_A, C_B, C_A⊕C_B, then crib at offset → candidate fragment of the other plaintext |
| `padding-oracle` | cipher, keyHex, ivHex, `plaintext` (text, ≤ 48 B), `detail: byte\|guess` | state, values, narration, wire | per target block, per byte (from the last): `guess` = one step per oracle query, `byte` = one step per recovered byte. The state holds C′, target C_i, intermediate I = D_k(C_i) and the recovered P. Narration params carry the query count. |

- **Worker:** the manifest flag `runIn?: 'main' | 'worker'` (optional, additive; default `main`).
  - The web host runs `worker` producers in a module Web Worker (`apps/web/src/labs/producer.worker.ts`).
  - The worker imports the primitive registry, calls `preparePorts` and `runPrimitive`, and posts the
    JSON bundle back.
  - A superseded run is terminated.
  - `padding-oracle` sets `runIn: 'worker'`. Everything is local and nothing touches the network.
- There is no `defineAttack` registry yet.

## 9. PenguinLab (dedicated island)

- `apps/web/src/islands/penguin/`:
  - an original flat-colour penguin SVG, rasterised to a canvas (no third-party image);
  - optional image upload (`<input type=file accept=image/*>`, downscaled to ≤ 256 px on the longest
    side; it never leaves the browser);
  - a mode switch ECB | CBC and a key field;
  - side-by-side original and encrypted.
- `penguin.worker.ts` resolves `aes` through the registry (`preparePorts`) and encrypts the RGB bytes
  with `core/modes` (alpha kept at 255). The ciphertext bytes are drawn back as pixels.
- Embedded in the lesson as `<PenguinLab />` (an Astro wrapper, messages assembled server-side under
  `ui.penguin.*`).

## 10. Lessons and navigation

- `symmetric/modes/{ecb,cbc,ctr,padding-oracle}.mdx` in EN and DE, with the six parts from
  AUTHORING:
  - **ecb:** penguin in the break part;
  - **cbc:** bit-flip in break;
  - **ctr:** keystream reuse and crib dragging in break;
  - **padding-oracle:** the whole lesson is the attack.
- Quizzes use stable ids (0b). `<Lens>` blocks are used where the cryptographer depth differs.
- Sidebar: in "Block ciphers", a nested group "Modes" (DE „Betriebsarten“) autogenerated from
  `symmetric/modes`, after AES.
- `e2e/lessons.spec.ts` gets a `MODE_LESSONS` list alongside `AES_LESSONS`.

## 11. PWA

- `@vite-pwa/astro` 1.2 still peers `astro ≤ 5`, so it is not used. Instead:
  - **Build:** a post-build step `apps/web/scripts/build-sw.mjs` runs `workbox-build` `generateSW`
    over `dist/` after `astro build`. Pagefind is written in `astro:build:done`, so its files are in
    the precache.
  - `navigateFallback: null`, `directoryIndex: 'index.html'`, and `maximumFileSizeToCacheInBytes`
    capped at 3 MB. The script prints the precache size and fails above 25 MB.
  - **Manifest:** `manifest.webmanifest`, with `scope`/`start_url` derived from `base`.
  - **Registration:** `workbox-window` with prompt-to-reload. A localized toast reads "New version
    available — Reload" (`ui.pwa.*`).
  - `CV_PWA=false` skips the service worker (PR previews, dev).
- **Offline e2e:** load a page, wait for the service worker to control it, go offline, then reload a
  lesson, another lesson and a lab, and check that each renders and runs.
