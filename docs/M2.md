# M2 — Foundations + S-box: design brief

Shared contract for everyone working on M2. Decisions here are binding; deviations get noted in
`docs/STATUS.md`.

## 1. Shared GF(2⁸) math moves to core

- `packages/primitives/src/aes/gf256.ts` → `packages/core/src/math/gf256.ts` (as planned in PLAN §7 M1).
  AES imports it from `@cryventure/core`.
- New pure "explain" functions in core return plain data, no i18n and no tracer:
  - `xtimeSteps(a)`: shift, carry bit, conditional ⊕ 0x1B.
  - `gmulSteps(a, b)`: Russian-peasant / shift-and-add over the bits of `b`.
  - `ginvSteps(a)`: a²⁵⁴ by square-and-multiply.
- `packages/core/src/math/rijndaelAffine.ts`: `AFFINE_CONSTANT`, `affine`, `affineSteps(x)` (one record
  per output bit: `b'ᵢ = bᵢ ⊕ bᵢ₊₄ ⊕ bᵢ₊₅ ⊕ bᵢ₊₆ ⊕ bᵢ₊₇ ⊕ cᵢ`), and `sboxEntry`. The AES plugin's
  `sbox.ts` reuses these.

## 2. New facets (one additive schema file each in `packages/core/src/facets/`)

### `math`: per-step equations
```ts
type MathOp = 'xor' | 'shift' | 'reduce' | 'mul' | 'square' | 'affine-bit' | 'result';
interface MathTerm {
  id: string;          // stable within the facet, e.g. 'acc', 'carry', 'p3'
  label: I18nRef;      // plugin.<id>.* key
  value: number;       // unsigned, < 2 ** width
  width: number;       // 1..32 bits (8 = GF(2⁸) element, 9 = unreduced product)
  role: 'operand' | 'intermediate' | 'constant' | 'carry' | 'result';
  op?: MathOp;         // how the term enters the computation
  bits?: number[];     // emphasised bit positions, 0 = LSB
  carryBit?: number;   // bit position that is the carry out (e.g. 8 for xtime's shifted value)
}
interface MathStep { step: number; formula: I18nRef; terms: MathTerm[] } // step = state-facet step index
interface MathFacet { kind: 'math'; schemaVersion: 1; notation: { field: 'gf2^8'; modulus: number }; steps: MathStep[] }
```
- `step` values are strictly increasing.
- `mathStepAt(facet, step)` returns the latest math step whose `step ≤ step`.

### `table`: lookup tables
```ts
interface TableFacet {
  kind: 'table'; schemaVersion: 1; title: I18nRef;
  rows: number; cols: number; entries: number[];  // entries.length === rows * cols, u8
  selected?: number;                              // highlighted input index
  selectParam?: string;  // producer param that receives a clicked index (2-digit hex for a 256-entry table)
}
```

## 3. Views may request a re-run

- `useLabActions().requestParams(patch)` is optional and wired by the web app.
- The app merges the patch into the current params, runs `producer.validate`, then re-runs exactly as the
  ParamPanel does. The ParamPanel shows the new values.

## 4. New plugins

| Plugin | Kind | Facets | Purpose |
|---|---|---|---|
| `primitives/gf256` | producer | state, values, narration, math | GF(2⁸) calculator: `op: xtime\|gmul\|ginv`, `aHex`, `bHex` |
| `primitives/aes-sbox` | producer | state, values, narration, math, table | S-box derivation for one byte: inverse (a²⁵⁴), then affine bit by bit |
| `primitives/xor` | producer | state, values, narration | XOR / one-time pad (foundations; also the generic "toy" e2e lab) |
| `primitives/endian` | producer | state, values, narration | integer → big-endian vs little-endian byte layout |
| `views/math` | view | requires `math` | bit strips + hex; polynomial notation in the cryptographer lens |
| `views/lookup-table` | view | requires `table` | 16×16 grid; click → `requestParams` |

The "SBoxExplorer" is a lab of `aes-sbox` with `lookup-table|math|narration` views. The "GF256Calculator"
is a lab of `gf256` with `math|state|narration` views.

## 5. Quiz + progress (apps/web)

- `apps/web/src/progress/`:
  - Pure module, localStorage key `cv.progress.v1`.
  - Shape: `{ version: 1, lens?, prologue?: { completedAt }, lessons: { [lessonKey]: { quiz: { [n]: { correct, attempts, lastAnswer } } } } }`.
  - Includes migrations (`migrate(unknown) → ProgressV1`), safe storage (never throws), a tiny subscribable store
    (`useSyncExternalStore`, cross-tab `storage` event), and JSON export/import with validation.
  - No new dependency (no nanostores).
- `lessonKey` is the page slug without base and locale (`symmetric/aes/subbytes-sbox`), so EN and DE share
  progress.
- `CheckQuestion.astro` keeps its props API and renders an interactive Quiz island. Authors still write
  questions in MDX, so existing lessons need no changes. **Deviation:** this replaces the bilingual YAML
  `quizzes` collection, keeping per-page translation and freshness checks.
- `/<lang>/progress/` page: per-lesson score, export, import, reset.

## 6. Lens

- Page-wide lens is `story | engineer | cryptographer`, stored in progress, default `engineer`.
  - It is reflected on `<html data-lens>`.
  - The header selector is a ThemeSelect override.
- `<Lens level="engineer">…</Lens>` shows for that lens and deeper; `<Lens only="story">` shows for exactly that lens.
- Lab islands follow the page lens live unless `Lab.astro` pins `lens`.
