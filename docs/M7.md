# M7 — MAC & KDF I (HMAC, KMAC, HKDF, PBKDF2, TLS PRFs): design brief

This is the shared contract for everyone working on M7. The decisions here are binding; record any
deviation in `docs/STATUS.md`. The format follows `docs/M6.md`.

M7 starts PLAN §6 Phase 2b. It has five parts:

- **The `Mac` port** (core) and **port members**: a port param can name one function inside a
  family (`sha256:sha-256`, `sha256:hmac-sha-256`), so combinators pick a hash or a MAC without
  hard-coding plugin ids.
- **MACs:** `HMAC(Hash)` as a shared plugin lib that every hash producer uses to expose `Mac`
  (HMAC-MD5, HMAC-SHA-1, HMAC-SHA-224/256/384/512, HMAC-SHA-512/t, HMAC-SHA3-*), keyed BLAKE2
  through the same port, and the traced labs `hmac` (ipad/opad, midstates, truncation,
  constant-time verification) and `kmac` (KMAC128/256 and KMACXOF on cSHAKE, SP 800-185).
- **KDFs:** `hkdf` (RFC 5869 Extract/Expand, plus the TLS 1.3 `HKDF-Expand-Label` preview) and
  `pbkdf2` (RFC 8018, the first producer that runs in a Web Worker).
- **TLS PRFs:** `tls12-prf` (RFC 5246 P_hash, P_SHA256 by default; RFC 7627 extended master secret
  as a preset) and `tls10-prf` (RFC 2246 P_MD5 ⊕ P_SHA-1).
- **The `derivation` view** (renamed from `key-schedule`) renders KDF DAGs with zoom links into the
  `hmac` lab and from there into the hash labs.

Lessons `mac/{index,hmac,kmac}` and `kdf/{hkdf,pbkdf2,tls-prf}` are new. EN first, then DE.

**Not in M7:** attack labs (user rule, §10); nested child traces (§1d); CMAC (needs Phase 4's
CMAC subkey story, comes with modes II), SSH KDF, SP 800-108/56C, scrypt, Argon2id, DRBGs (later
Phase 2b milestones); BLAKE2 salt/personalization; x86 SHA-512; `SHA256_CTX` in the memory deriver.

## 1. Core

### 1a. The `Mac` port

```ts
/** How a MAC is built: metadata for zoom links and combinator filters, not behaviour. */
export type MacConstruction =
  | { readonly kind: 'hmac'; readonly hash: string }   // the Hash member ref, e.g. 'sha256:sha-256'
  | { readonly kind: 'kmac' }
  | { readonly kind: 'keyed-hash' };                    // keyed BLAKE2 (RFC 7693 §2.5)

/** KMAC's S and L (SP 800-185 §4.3); absent = empty S, default length. */
export interface MacOptions {
  readonly customization?: Uint8Array;
  readonly outputLength?: number;
}

/** A running MAC computation keyed once: update* → mac. */
export interface MacContext {
  /** Absorbs more data; the caller may reuse `data` afterwards. */
  update(data: Uint8Array): void;
  /** The tag of everything absorbed so far; does not change the context. */
  mac(): Uint8Array;
  /** An independent copy (for HMAC: both midstates; PBKDF2 clones one per iteration). */
  clone(): MacContext;
}

export interface MacFunction {
  readonly id: string;              // 'hmac-sha-256', 'hmac-sha3-256', 'kmac128', 'blake2s-256'
  readonly outputSize: number;      // the default tag length in bytes (KMAC128: 32, KMAC256: 64)
  readonly blockSize: number;       // HMAC: the hash's B; KMAC: the rate; BLAKE2: the block
  readonly keySizes: { readonly min: number; readonly max?: number }; // bytes; no max = unbounded
  readonly customizable: boolean;   // accepts MacOptions.customization (KMAC only)
  readonly variableOutput: boolean; // accepts MacOptions.outputLength (KMAC only)
  readonly construction: MacConstruction;
  /** Throws a RangeError on a key outside `keySizes` or options the function does not accept. */
  mac(key: Uint8Array, data: Uint8Array, options?: MacOptions): Uint8Array;
  create(key: Uint8Array, options?: MacOptions): MacContext;
}

export interface MacFamily {
  readonly id: string;                        // the producer id, e.g. 'sha256', 'blake2', 'kmac'
  readonly functions: readonly MacFunction[];
}
export function macFunction(family: MacFamily, id: string): MacFunction | undefined;
```

- `PortMap` gains `Mac: MacFamily`; `PORT_NAMES` follows from the `PORTS` record.
- **`HashContext.chainingState?(): Uint8Array`** (optional, additive): the internal chaining value
  without buffered bytes (MD/SHA-2: the H words in the spec's byte order; sponge: the 200-byte
  state; BLAKE2: h in little-endian). For teaching midstates only. `_lib/hashKit`, `_lib/keccak`
  and `_lib/blake2` implement it in wave 2.
- **`PORT_SANITY.Mac`** (tools, commit 1): sizes; `keySizes.min ≥ 0`, `max ≥ min`; per function for
  key lengths {min, 1 (if allowed), blockSize, blockSize + 1 (if allowed)} and messages
  {0, 1, blockSize, 2·blockSize + 3} bytes: deterministic, non-mutating `mac`; `create(key)` +
  `update` over the splits used for `Hash` equals `mac`; `mac()` twice equal; `clone()` independent
  both ways; a key outside `keySizes` throws `RangeError`; options a function does not accept
  throw; for `kind: 'hmac'` the tag differs for two keys that differ only after byte `blockSize`
  when the key is hashed first (RFC 2104 §2: K longer than B is hashed) — i.e. it proves the
  long-key branch exists.

### 1b. Port members

A family port (`Hash`, `Mac`) offers several functions. A **member ref** names one:
`"<producerId>:<memberId>"` (`sha512:sha-512/256`, `sha256:hmac-sha-256`, `blake2:blake2s-256`).
Producer ids are kebab-case and member ids never contain `:`.

```ts
// ports.ts
export type MemberPortName = 'Hash' | 'Mac';
export interface PortMemberMap { Hash: HashFunction; Mac: MacFunction }
export function portMemberRef(producerId: string, memberId: string): string;
export function parsePortMemberRef(ref: string): { producerId: string; memberId: string } | undefined;
export function portMember<N extends MemberPortName>(port: N, family: PortMap[N], memberId: string): PortMemberMap[N] | undefined;

// registry.ts — PrimitiveManifest (additive)
export interface PortMemberDecl {
  id: string;
  labelKey: string;              // in the producer's namespace, e.g. 'plugin.sha256.mac.hmac-sha-256'
  construction?: MacConstruction['kind'];   // Mac members only
}
portMembers?: Partial<Record<MemberPortName, readonly PortMemberDecl[]>>;

// params.ts — ParamField (additive)
member?: true;                                  // a `port` field whose value is a member ref
constructions?: readonly MacConstruction['kind'][]; // Mac member fields: allowed constructions
```

- Hash members are `HashFamily.functions` only (not XOFs; no M7 consumer needs an XOF port).
- `portOptions(producers, field)` lists, for a member field, one option per declared member of
  every producer implementing the port (value = member ref, label = member `labelKey`), filtered by
  `constructions`, sorted by producer id then declaration order. Non-member fields are unchanged.
- `preparePorts` loads the producer named by the ref's producer part. **`requirePortMember(resolve,
  port, ref)`** returns `{ ok, member, producerId, memberId }` or `core.error.portMissing` /
  `portLoadFailed` / a new `core.error.portMemberMissing` (`{{id}}`) run error.
- `readPortMemberRef(input)` for `validate()` (kebab-case producer, non-empty member).
- **Contract kit:** for every producer, the declared `portMembers` ids equal the loaded port's
  member ids in order (Hash: `functions`; Mac: `functions` and each `construction.kind`); every
  member `labelKey` exists in EN and DE (identical EN/DE values allowed for names such as
  "HMAC-SHA-256"); member fields have `port` ∈ `Hash | Mac`.

### 1c. Why port members, not a select per consumer

A select with hard-coded options (`sha-256`, `sha-512`, …) in `hmac` or `hkdf` would name other
plugins' functions in code, so a new hash plugin would need edits elsewhere (breaks PLAN §2b
open/closed). With members, a new hash producer declares its functions once and appears in every
HMAC/HKDF/PBKDF2/PRF picker.

### 1d. Nested child traces: not now

`TraceBundle.children` (a combinator call opening a scoped child trace) stays deferred. M7 gets the
drill-down with **zoom links** instead (the M3 `blockLabParams` precedent): HKDF/PBKDF2/PRF nodes
link to the `hmac` lab with that call's key and message, and the `hmac` lab's inner and outer hash
nodes link to the hash lab with the exact hash input (`hashLabParams`, §1e). Every hop is a real,
deterministic lab run. Children need changes to the trace type, tracer, timeline, web host and
contract kit, and the first consumer that needs linked brushing *across* levels is TLS 1.3
(Phase 7); decide there.

### 1e. Backlog items in commit 3

- **Validator gaps** (M6 reviews), each reproduced by a failing test first: validators check
  `kind`; reject NaN/±Infinity in numeric facet fields and `stepCount: NaN`; wordops rejects a
  transfer source with both `register` and `term`; `latestStepAt` documents and asserts sorted
  input (or sorts; agent's choice, with a test); core's `mathStepAt`/`fieldStepAt` copies become
  `latestStepAt` (behaviour unchanged, tests prove it).
- **Per-field encoding:** `ParamField.encodingParam?: string` names the sibling select whose value
  `'hex'` makes this text field hex-measured (panel + contract kit). `textFieldByteLength` uses the
  declaration instead of the `input` name convention; `hashKit`/`sha3`/`blake2`/`md5`/`sha1`
  manifests declare `encodingParam: 'encoding'` on `input` in the same commit. M7 producers declare
  their own (e.g. `password` + `passwordEncoding`).
- **`PrimitiveManifest.hashLabParams?(functionId, messageHex): Record<string, string> |
  undefined`** (additive): the params of this producer's own lab hashing `messageHex` with
  `functionId`, or `undefined` if the lab cannot (message too long, unknown function). Implemented
  once in `hashKit/manifestKit` for SHA-2/MD5/SHA-1 and by `sha3`, `blake2`. Used by the `hmac`
  zoom links and by the tools hash cross-check (replacing its hard-coded param names: this is the
  "port-call hook" backlog item for `Hash`).

## 2. Producers

### 2a. Plugin libs (untraced references)

- **`_lib/hmac/`:** `hmacFunction(hash: HashFunction, ref: string): MacFunction` (RFC 2104 /
  FIPS 198-1: K0 = K if |K| = B, H(K) ‖ 0* if |K| > B, K ‖ 0* otherwise; ipad 0x36, opad 0x5c;
  B = `hash.blockSize`, which is the rate for SHA3 per FIPS 202/SP 800-224); the context keyed once
  holds the inner and outer midstates (`create()` + `update(K0 ⊕ pad)` then `clone()` per
  message), so `MacContext.clone()` copies two hash contexts, never the key. `hmacFamily(hash
  family, producerId, ids)` and a `manifestKit.ts` helper building the `portMembers` declarations.
  `timingSafeEqual(a, b)` (no early exit, length mismatch returns false after a full pass over the
  expected tag) for the lab's verify step.
- **Mac on the hash producers** (wave 2): `sha256` (hmac-sha-224, hmac-sha-256), `sha512`
  (hmac-sha-384, hmac-sha-512, hmac-sha-512/224, hmac-sha-512/256), `sha3` (hmac-sha3-224…512; no
  HMAC-Keccak-256), `md5` (hmac-md5), `sha1` (hmac-sha-1): `implements: ['Hash', 'Mac']`.
  `blake2` exposes keyed BLAKE2 (`construction: keyed-hash`, ids = the eight hash ids, `keySizes`
  1…32 / 1…64; key length 0 is the unkeyed hash, not a MAC, and throws). `kmac` exposes kmac128,
  kmac256 (`construction: kmac`, customizable, variable output).
- **`_lib/prf/`:** `pHash(mac, secret, seed, length)` (RFC 5246 §5) as an untraced function and a
  recorder helper shared by both TLS PRF producers.
- **SHA-512 hi/lo port** (backlog): `_lib/sha2` gets a 32-bit hi/lo `Uint32Array` compression for
  the **port** (`HashFunction`/contexts) of the SHA-512 family; the traced producer keeps `bigint`.
  Tests: equal to the `bigint` path on the CAVP sets; port speed ≥ 10× the `bigint` path.
  Keccak/BLAKE2b hi/lo only if §2e's budget fails for them.

### 2b. `hmac` (traced lab, `HMAC(Hash)`)

**Params:**

| Param | Kind | Notes |
|---|---|---|
| `hash` | port `Hash`, `member` | default `sha256:sha-256` |
| `key` | text, hex | ≤ 256 bytes (RFC 4231 tests 6/7: 131), may be empty |
| `encoding` | select | `utf8` \| `hex` |
| `input` | text, `encodingParam: 'encoding'` | ≤ 256 bytes (RFC 4231 test 7: 152) |
| `tagLength` | select | `full` (default) \| `32` \| `28` \| `24` \| `20` \| `16` \| `12` \| `10`; run error unless `max(10, L/2) ≤ t ≤ L` (RFC 2104 §5, FIPS 198-1 §5) |
| `expected` | text, hex | optional tag to verify (empty = compute only) |

**Ops** (scope `op` only): `keyPrep` (K0: as is, zero-padded, or hashed then padded; the narration
says which branch and why), `ipad` (K0 ⊕ 0x36…; `math` bit strips of 0x36, 0x5c and their XOR 0x6a:
the pads differ in 4 of 8 bits per byte), `innerBlock` (compress K0 ⊕ ipad: the inner midstate,
`chainingState` when available), `innerMessage` (absorb the message, inner digest), `opad`,
`outerBlock` (outer midstate), `outer` (absorb the inner digest, outer digest), `truncate` (when
t < L), `verify` (when `expected` is set: byte-wise XOR accumulation, the narration explains why the
loop never exits early; PASS/FAIL).

**Facets:** `state` (regions `key`, `k0`, `ipadKey`, `innerState`, `message`, `inner`, `opadKey`,
`outerState`, `tag`, `expected`; midstate regions only when the hash offers `chainingState`),
`values` (`key` role `key`, `k0`/`ipadKey`/`opadKey`/midstates `secret`, `message` `public`, `tag`
`public`), `derivation` (key → K0 → ipad/opad keys → inner → tag; inner and outer nodes carry a
`zoom` to the hash lab via `hashLabParams` of the hash's producer when it returns params), `math`
on `ipad`/`opad`, `narration`. **Outputs:** `{ tag }` (and `{ verified }` as `01`/`00`).

**Presets:** `rfc4231-tc1` (default, HMAC-SHA-256), `rfc4231-tc2` ("Jefe"), `rfc4231-tc5-trunc`
(128-bit tag), `rfc4231-tc6-longkey` (131-byte key: the hashing branch), `rfc2202-md5-tc1`,
`rfc2202-sha1-tc1`, `hmac-sha512-tc1`, `hmac-sha3-256-sample` (a NIST/Wycheproof case),
`verify-pass`, `verify-fail` (tag differs in the last byte).

**"Why these constants" (ipad/opad):** Bellare–Canetti–Krawczyk (CRYPTO 1996, §5/§6) and RFC 2104
§2: any two distinct pads would do for the proof as long as K0 ⊕ ipad and K0 ⊕ opad differ; 0x36
and 0x5c are fixed so implementations interoperate and differ in half their bits. The lesson cites
the paper; it does not claim a deeper derivation.

### 2c. `kmac` (traced lab on cSHAKE)

SP 800-185 §4: `KMAC128(K, X, L, S) = cSHAKE128(bytepad(encode_string(K), 168) ‖ X ‖
right_encode(L), L, "KMAC", S)`; KMACXOF uses `right_encode(0)`.

- Params: `algorithm` `kmac128` | `kmac256` | `kmacxof128` | `kmacxof256`; `key` hex (≤ 64
  bytes); `encoding` + `input` (≤ 200 bytes, `encodingParam`); `customization` text (UTF-8, ≤ 64);
  `outputLength` select 16/32/64/168; `detail` `permutation` (default) | `round` | `mapping`.
- Recording reuses the sponge recording of `sha3`: move what both need into `_lib/keccak` (the
  `sha3` goldens and bundle fixtures stay **byte-identical**; a test proves it). Ops: `encodeKey`
  (bytepad(encode_string(K))), `encodeLength` (right_encode(L)), then the cSHAKE ops of `sha3`
  (`pad` names N = "KMAC" and S).
- Facets: `state`, `values` (`key` role `key`), `sponge`, `narration`; Outputs `{ tag }`.
- Port: `ports.Mac` = family `kmac` {kmac128, kmac256} (the XOF variants are lab-only).
- Presets: SP 800-185 KMAC samples 1–6 (`kmac128-sample1` default) and KMACXOF samples 1, 4.

### 2d. `hkdf`

**Params:** `mac` (port `Mac`, `member`, `constructions: ['hmac']`, default `sha256:hmac-sha-256`);
`mode` `hkdf` (default) | `extract` | `expand` | `expand-label`; `ikm` hex (≤ 128); `salt` hex
(≤ 128, empty = HashLen zero bytes, RFC 5869 §2.2); `prk` hex (expand modes, ≥ HashLen, ≤ 128);
`infoEncoding` + `info` (≤ 128, `encodingParam`); `length` text, digits 1…255 (and ≤ 255 · HashLen,
RFC 5869 §2.3); `label` text (expand-label, ≤ 249 bytes so "tls13 " + label ≤ 255, RFC 8446 §7.1)
and `context` hex (≤ 255, typically a transcript hash).

**Ops:** `extract` (PRK = HMAC(salt, IKM)), then per block i `expand` (T(i) = HMAC(PRK, T(i−1) ‖
info ‖ i)), `output` (OKM = first L bytes). `expand-label` adds `hkdfLabel` first: the struct
`uint16 length ‖ u8 len ‖ "tls13 " ‖ label ‖ u8 len ‖ context` (shown byte by byte in a `state`
region and named fields in the narration), then expand with that as info.

**Facets:** `state` (`ikm`, `salt`, `prk`, `info`/`hkdfLabel`, `t` (the current T(i)), `okm`),
`values` (`ikm`/`prk`/`okm` `secret`, `salt`/`info` `public`), `derivation` (title "HKDF"; result
nodes PRK and each T(i), OKM; each HMAC node has `zoom` to the `hmac` lab when its key and message
fit the lab's limits), `narration`. **Outputs:** `{ prk?, okm }`.

**Presets:** `rfc5869-a1` (default), `rfc5869-a2` (long inputs), `rfc5869-a3` (empty salt and
info), `rfc5869-a4` (SHA-1), `rfc5869-a7` (SHA-1, no salt), `tls13-derived` (RFC 8448
Derive-Secret(early secret, "derived", "") = Expand-Label with context = SHA-256("")),
`tls13-c-hs-traffic` (RFC 8448 "c hs traffic" with its printed transcript hash).

### 2e. `pbkdf2`

**Params:** `mac` (member, `constructions: ['hmac']`, default `sha256:hmac-sha-256`);
`passwordEncoding` + `password` (≤ 128 bytes); `saltEncoding` + `salt` (≤ 128); `iterations` text,
digits 1…100000; `length` text, digits 1…128.

**Recording:** per block i: `u1` (U₁ = PRF(P, S ‖ INT(i))), `u` for j = 2…c, `xor` (F ⊕= U_j);
when c > 8 only j ≤ 3 and j = c are recorded, with one `skip` step between ("U₄ … U_{c−1}: c − 4
HMAC calls, not shown") whose F is the real running value at j = c − 1; then `block` (T_i) and
`output`. Scope `block → iteration`; the iteration level label reads "Iteration j of c". The
`state` region `cost` (text in narration, not bytes) is not needed: the narration of `output`
states the total number of HMAC calls and compressions (2 per call after the midstates).
Computation uses `MacContext.clone()` from one keyed context (the midstate trick), never
re-keying per iteration.

**`runIn: 'worker'`** (first producer to use it; prune the worker graph duplicates if the precache
grows by more than 100 KB). **Budget test:** PBKDF2 with every HMAC member at 100000 iterations
and 32 bytes must finish in < 10 s under the test runner; members that fail it get the hi/lo port
(§2a) or a documented lower cap. Facets: `state` (`password`, `salt`, `u`, `f`, `dk`), `values`
(`password` role `secret`, `dk` `secret`), `derivation` (U₁ … U_c chain with zoom on U₁),
`narration`. Presets: `rfc6070-tc1` (default, c = 1), `rfc6070-tc2` (c = 2), `rfc6070-tc3`
(c = 4096), `rfc6070-tc5` (long password/salt, dkLen 25), `rfc7914-sha256-c1`,
`rfc7914-sha256-c80000`.

### 2f. `tls12-prf` and `tls10-prf`

- **`tls12-prf`** (RFC 5246 §5): `PRF(secret, label, seed) = P_<hash>(secret, label ‖ seed)`;
  `P_hash` = HMAC(secret, A(i) ‖ seed) with A(0) = seed, A(i) = HMAC(secret, A(i−1)). Params:
  `mac` (member, hmac only, default `sha256:hmac-sha-256`; P_SHA384 only for RFC 5289 suites, said
  in the lesson), `secret` hex (≤ 256), `label` text (≤ 64, ASCII), `seed` hex (≤ 128), `length`
  digits 1…256. Ops: `seed` (label ‖ seed), `a` (A(i)), `p` (HMAC(secret, A(i) ‖ seed)), `output`.
- **`tls10-prf`** (RFC 2246 §5): S1 = first ⌈|secret|/2⌉ bytes, S2 = last ⌈|secret|/2⌉ (they share
  the middle byte when odd); `PRF = P_MD5(S1, label ‖ seed) ⊕ P_SHA-1(S2, label ‖ seed)`. Params as
  above minus `mac`, plus `md5Mac` and `sha1Mac` member fields (defaults `md5:hmac-md5`,
  `sha1:hmac-sha-1`; the narration states that RFC 2246 fixes them). Ops: `split`, the two P_hash
  chains (scope `half → op`), `xor`, `output`.
- Facets: `state`, `values` (`secret`/`output` `secret`), `derivation` (A(i) chain, P blocks, zoom
  to `hmac`), `narration`. Shared recorder in `_lib/prf`.
- **Presets:** `tls12-master-secret` (default, a CAVP SP 800-135 TLS 1.2 SHA-256 case:
  "master secret", client_random ‖ server_random, 48 bytes), `tls12-key-expansion` ("key
  expansion", server_random ‖ client_random), `tls12-ems` (RFC 7627 "extended master secret" with
  a session hash seed), `tls12-sha384` (a CAVP SHA-384 case), `tls10-master-secret` (a CAVP TLS
  1.0/1.1 case).

## 3. Facet schemas (wave 1, commit 2)

```ts
/** A link to another producer's lab run (generic successor of the chain facet's block zoom). */
export interface LabZoom {
  producerId: string;
  params: Record<string, string>;
}
// DerivationNode (additive): zoom?: LabZoom;
```
